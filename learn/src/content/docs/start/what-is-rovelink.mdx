RoveLink lets you drive a real robot, over the internet, from a browser tab. That's the entire idea. Everything else in this site is _how_ — this page is just _what_.

## Four steps

1. **You** press a key, touch the screen, or move a game controller.
2. **Your browser** turns that into a small, constantly-updated "drive like this" message.
3. **A relay in the cloud** (Cloudflare) passes your message to the one robot you're allowed to drive — and only your messages, never anyone else's.
4. **The robot** double-checks the message makes sense, then turns its wheels.

## Why this is harder than it sounds

A robot obeying stale or out-of-order commands is a safety problem, not a bug report. RoveLink is built around a handful of rules that make that impossible by construction:

- **Latest state wins.** There is no command queue anywhere in the pipeline — from the browser down to the firmware. An old command can never play back after a newer one has already arrived.
- **A watchdog, not good faith.** Every driving message carries an expiry. If messages stop arriving — Wi-Fi drops, a tab freezes, Cloudflare hiccups — the robot stops on its own, well before anyone would notice something is wrong.
- **Sessions, not just sequence numbers.** Reconnecting mints a brand-new authority. A delayed message from before the reconnect can never sneak back in and override what's current.

You'll see all three of these live, with real numbers, in the [Control Flow Lab](/labs/control-pipeline/).
